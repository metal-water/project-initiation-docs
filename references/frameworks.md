# 框架与模板

新写时以用户模板为起点。用户指定新模板或要求保留旧稿时，不把以下八章当作重写旧稿的理由。原模板页数不是成稿页数指标。

## 立项报告

原模板15页，含封面、自动目录与八章。封面包括项目名称、年度、起止年月、主持部门、负责人。原版有蓝色多级标题、页眉和页码；保留的模板样式不被通用设计规范强行替换。

| 章节 | 应写内容 | 约束 |
| --- | --- | --- |
| 1 立项背景和意义 | 研究背景、研发目的、产品与技术需求、市场或应用前景 | 贴合品类和项目阶段，不套金融APP背景，不凭空引用市场规模 |
| 2 研究开发内容和目标 | 按专题写研究内容、技术难点、创新点或新知识、技术或经济指标 | 重点章。将玩法、客户端、服务端、制作工具、适配测试等组织为实际研发专题，不只是功能名清单 |
| 3 现有研发条件和工作基础 | 已有技术、工具、素材、工作基础和可复用成果 | 已具备事实与本轮计划分开；不把原公司的荣誉、人数和资产归给新主体 |
| 4 项目编制及人员 | 主持部门、角色分工、负责人及人员表 | HRBP待填时人数为空标黄；姓名与人数区分，按用户范围处理 |
| 5 预期成果归属 | 预期交付、成果类型、知识产权和权属 | 主体变化不等于历史IP转移，未知权属不擅自断言 |
| 6 项目经费总预算 | 预算总额、科目和单位 | 默认金额标黄留空；不能删整个章节代替留空 |
| 7 计划工作进度 | 时间、阶段、研究活动和阶段成果 | 使用已确认周期或用户授权的拟定计划，与决议对齐 |
| 8 风险与效益分析 | 技术、制作、性能、兼容、进度等具体风险与措施；有依据的预期效益 | 不把目标写成已实现营收或验证过的ROI |

专题用连贯段落交代“问题、研究内容、难点、成果、验证方式”。图放相应内容旁并解释用途。模板提示“至少三个专题”不构成虚构专题的理由。

清理金融APP、企业微信、Flink-CDC等例文、示例数字日期、红色写作提示和标题中的撰写说明。复核旧页眉页脚和未启用部件，避免节设置变化显露其他公司、年份或文种。更新TOC、PAGEREF等域并保存。

## 立项决议

原始参考3页，实际是研发延期请示。可沿用版式组成，但事项按本次目的写：

1. 正式标题：项目全称及确认的决议文种。
2. 受文／决策主体与事项说明：立项原因、研发范围、拟实现目标。
3. 项目实施计划：与报告相同周期和主要阶段，可概括。
4. 项目预算：保留总额、科目、单位，按规则填写或黄色空白。
5. 呈报部门意见、会签部门意见，以及模板所需审批／签署栏。

用户要求从延期稿另编正常立项决议时，标题、延期原因、原结项节点、延期区间、延期经费、请示事项和表格均要统一调整。未签批保持真实待审状态。用户仅咨询差异时先解释，不自动改历史批准日期。
